# 分类、检索与交付

## 本机分类

输出根目录由用户设置，例如 `<OUTPUT_ROOT>`。先判断用户要的成果，再选目录；不要仅凭平台名分类。一次需求选一个主分类、创建一个任务目录，跨站、换关键词和续接始终复用它。用户明确指定路径优先。

| 需求 | 分类目录 | 应保存的成果 |
| --- | --- | --- |
| AI 赚钱教程、案例拆解、实操步骤 | AI赚钱实操 | 原帖图文 HTML、来源与缺项；区分作者收益自述和可验证事实 |
| TikTok、抖音等爆款视频收集 | 爆款视频 | 下载的可播放视频、封面、来源及当时互动量；未取得文件不能算下载成功 |
| 招投标、企查查、1688、企业与供应商信息 | 获客系统 | 企业/公告/产品明细 HTML 或 CSV、逐字段来源和获取时间；未知值留空 |
| 指定知乎、Reddit、X 等文章或文案 | 爆款文案 | 保留原文顺序、作者、图片和链接的 HTML；未要求改写时不改写 |
| UI、海报、品牌、IP 设计参考 | 宣传设计 | 主题 HTML、图词对应、原帖标题链接；提示词忠实于来源 |
| 没有指定方向的一般搜索、能力复测 | 根目录 raw | 一个编号任务档案；整理结果放在根目录 |

有明确的新类别且以上均不适合时，先询问是否新建该分类；用户回答前可使用默认 raw 保存本次检索，不能悄悄创建新的分类目录。不要为每个平台另建顶层分类。

所有已选分类采用同一结构：

```text
<输出根>/<分类>/
  NNN_原标题.html            成品，与 raw 同级
  NNN_视频说明.html          可选的成品索引
  raw/
    NNN_本次用户需求/        一项需求只创建一次
      luz-task.json
      search-*.json
      raw/...                来源分档、快照、媒体、哈希和续接任务
```

先 `begin "需求名" --out "<输出根>/<分类>" --new`，后续所有命令 `--out` 使用它返回的绝对 folder。新任务的成品自动写回分类根目录；来源和下载媒体仍在该任务内，成品使用相对路径访问。批量搬动成品时须连同所引用 raw 一起搬动。历史任务继续使用旧的路径约定，不自动迁移。

## 根据需求扩展关键词

先写清主题、所需成果、目标平台、数量/时间范围和什么才算有用。没有指定数量时先取得可判断相关性的候选，再按缺项增量采集；不要把“打开了网站”当作找到需求内容。

从用户原词开始。再扩展同义词、行业词、英文术语、方法和交付形式，每轮根据实际结果选词。示例：AI 赚钱可展开为 AI 工具订阅、独立开发、获客、收入复盘；海报参考展开为餐饮海报、品牌 KV、poster、完整提示词；企业采购展开为产品词、地区、招标公告、中标公告、供应商和公司全称。保留每个查询及采用原因，不能用一套固定关键词覆盖所有用户。

多站任务执行 [网站调研流程](site-research.md)：先从网站库选相关入口，再补本轮发现的新站，写入唯一任务的 `platform-plan.json` 后逐项实测。独立站点可用 batch 并发，每站动作仍按顺序执行，共用任务目录。范围包括国家/地方采购、企业/总包/开发商、行业与外贸、第三方电商数据、官方创作者与商家后台、趋势报告、设计与素材。真实表单、分类、榜单、分页和详情分别验证；空壳先诊断加载与控件，不能用索引摘要替代。候选库与运行 catalog 分开，只有验证过的可复用路线才进入 catalog；完整要求和字段以链接文档为准。

需要多站多词时，用 Agent 编写的 JSON 计划给 collect --file：

```json
[
  {"platform":"x","query":"AI SaaS 收入 复盘","reason":"查实操及交付"},
  {"platform":"reddit","query":"AI SaaS first customers","reason":"补获客与失败经验"}
]
```

先汇集、规范化并去重候选链接，再逐条打开需要的原文。每条核对标题/正文是否回答用户问题、作者、发布日期（可得时）、目标内容 ID、图片/音视频和已加载评论；不能拿推荐卡片、导航、平台介绍或搜索摘要代替目标。

`search --read N` 默认按搜索返回顺序打开前 N 个候选，只适合作为连通与解析复测，不能作为需求相关性的自动证明。生产调研先 `--read 0`，由 Agent 选择真正符合要求的 URL 再 capture / batch。实操教程须包含实际步骤或可演示操作；研修班通知、招生、引流软文即使出现全部关键词也不能充当教程。没有合适结果时换专业词、同义词或平台，不硬凑数量。

正文缺失先检查展开、分页、滚动和真实入口。可关闭的登录弹层先尝试公开阅读；确需登录、验证码或后台权限时保留同一来源的可见页面和 task_id，请用户处理。等待期间可继续不依赖该权限的工作；完成后 continue 并复核目标正文。冷却只展示来源证据并停止该站，不能换账号、入口或等待页重试规避。

## 分类别的验收

- 视频：视频文件存在、实际 MIME/哈希、画面与音轨可读分别核验；互动量只是采集时观察值，按用户阈值判断“爆款”。blob、HLS、DRM 或受限资源若没有可下载的页面资源，登记缺项，不虚构已下载。
- 企业：公司名、来源链接和采集时间必备；只保存页面公开可见、与需求有关的企业字段。详情受限时不要用搜索卡片补造联系人、资质或经营状态。介绍页不能代替灰豚、蒲公英等后台数据。
- 文案：连续原文、原有顺序和媒体按实际取得范围保留；拼接、翻译、分析需另行标记，不能覆盖 raw。
- 设计：左图与右侧提示词紧凑对齐、图片间少量间距，标题链接到原帖。去掉图下无关说明、编号来源等装饰；不把一条提示词自动套到同帖所有图片。未核对条目保留为待核对。
- 所有任务：搜索、正文、媒体下载、完整性、文件哈希与页面关闭分别记录。经验仅沉淀验证过的路线、失败原因与有效关键词；不能自动学习凭据或把一次成功当作永久可用。

整理完成按 raw-retention.md 先计划再清理可复采的大文件，保留来源 URL、哈希、交付信息、清理记录。等待人工处理的任务和唯一素材不清理。
